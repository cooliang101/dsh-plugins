# 悬浮助手需求

## 产品范围

悬浮助手是独立的 Windows 桌面插件。它管理屏幕右侧的半隐藏把手、展开和收起、置顶、焦点恢复及面板切换。已安装的插件可以通过统一约定贡献面板。用户可逐个启停面板，并选择默认打开的面板。

首版由宿主统一渲染标题、摘要、列表和操作按钮。接入方通过配置声明面板，通过注册的处理器提供动态数据和执行操作。

## 浮窗交互

| 状态 | 进入和退出规则 |
| --- | --- |
| 收起 | 启动后默认收起，目标显示器右侧只露出把手。点击把手展开。把手出现、数据刷新或插件注册时，前台应用继续接收键盘输入。 |
| 展开 | 打开默认面板，显示面板切换、刷新和收起入口。点击收起、在浮窗获得键盘焦点时按 Esc，或把焦点切到其他窗口时，回到把手。 |
| 截图中 | 在截图遮罩打开前临时隐藏面板和把手。截图结束、取消或失败后恢复此前的可见状态，并按操作结果刷新面板。若悬浮助手已停用，则保持隐藏。 |
| 停用 | 隐藏浮窗并清理窗口资源。重新启用时按启动规则恢复。 |

- 把手和面板置顶，只有实际显示的区域响应鼠标。目标显示器首版默认取主屏，允许用户从设置中选择。按该显示器工作区右侧定位，使用该屏的缩放比例。显示器拔除后回到主屏，分辨率、缩放或任务栏位置变化后重新定位。[Windows 多显示器定位](https://learn.microsoft.com/en-us/windows/win32/gdi/positioning-objects-on-multiple-display-monitors)
- 用户主动展开时记录此前的前台窗口。主动收起时，若浮窗仍持有前台焦点且原窗口仍有效，则尝试恢复。若用户已切到别处、操作已打开 DSH 主界面，或系统拒绝切换，保留系统当前的焦点处理结果。[Windows 前台窗口切换规则](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)
- 普通桌面和无边框窗口是首版交付场景。独占全屏记录可见性和交互结果，浮窗不可用时可通过 DSH 主界面使用对应功能。
- 展开高度随内容变化，上限为 460 DIP，并受目标显示器工作区限制。超过上限时，标题栏保持可用，内容区显示自定义滚动条。

## 面板设置

- 按用户保存目标显示器、各面板启停状态和默认面板，面板偏好以插件 ID 与面板 ID 的组合作为键。新发现的有效面板默认启用。
- 每次从把手展开时优先打开已配置的默认面板。默认面板不可用时，按插件 ID、面板 ID 的固定顺序选择第一个可用面板。当前面板被停用或移除时立即用同一规则回退。零面板时保留设置入口并提示启用或安装面板。
- 临时切换面板只影响本次展开。只有在设置中选择默认面板才更新持久化偏好。插件停用或卸载时保留偏好，同一面板重新注册后可以再次生效。

## 面板声明

| 字段 | 约定 |
| --- | --- |
| `version` | 接口版本。首版为 `1`。宿主对不支持的版本给出诊断。 |
| `id` | 稳定的面板 ID，在所属插件内唯一。宿主以插件 ID 和面板 ID 共同识别面板。 |
| `title` | 面板在切换列表中的显示名称。 |
| `provider` | 读取面板数据的处理器 ID，由所属插件注册。 |
| `actions` | 操作声明列表。每项提供稳定的操作 ID、按钮文字和所属插件注册的处理器 ID。 |

插件启用时加载声明，停用或卸载时移除贡献。缺失处理器、重复 ID 或无效声明只影响对应面板，并提供可定位到插件和面板的诊断。

声明和处理器由所属插件在同一次注册中提交，宿主校验后再将有效面板发布给界面。处理器在所属插件的注册范围内解析。首版以纯文本渲染内容，界面只提供声明过且当前可用的操作。

## 数据接口

- **输入**为面板 ID。接入方从自身管理的状态中确定当前上下文，例如 GameGuide 的当前游玩档案。
- **输出**包含 `status`（`ready` 或 `empty`）、可选的 `summary`、`items` 和 `availableActions`。列表项包含稳定 ID、文字及可选状态说明。可用操作必须引用声明中已有的操作 ID。
- **操作上下文**。若操作依赖当前档案或选中项，数据提供器为该操作附带不透明的 `contextToken`。宿主在点击时原样回传，接入方验证它是否仍适用。
- **刷新与失败**。首次展开、切换面板和用户主动刷新时读取数据。插件状态变化时可通知宿主刷新对应面板。宿主在面板内显示加载、空状态和失败反馈。切换后的面板仅渲染与其当前请求对应的结果。

每次重新展开都读取最新数据。收起时暂缓通知触发的读取。切换面板、重新刷新或移除贡献时，使旧读取失效，即使之后切回同一面板也丢弃其迟到结果。刷新中和读取失败时禁用上一份快照的操作，失败后提供重试入口。数据提供器超时或抛错按读取失败处理。

## 操作接口

- **输入**为面板 ID、操作 ID，以及数据接口为该操作返回的可选 `contextToken`。宿主按声明调用面板所属插件的处理器。
- **输出**包含 `status`（`ok` 或 `error`），以及可选的用户可读消息和刷新请求。打开详情、发起截图、继续对话等行为由接入方执行。
- **执行规则**。运行中禁用该次操作的按钮，避免重复点击。上下文已变化时，处理器返回提示并请求刷新，让玩家看到新状态后重新操作。失败反馈显示在发起操作的面板内。

宿主以面板和操作 ID 跟踪执行状态，切走再切回时仍防止同一操作重复提交。返回的刷新请求只影响来源面板。插件移除后丢弃迟到的操作结果。操作等待超时只表示执行结果未知，界面提示用户查看实际状态，宿主不自动重试。

## 接入分工

| 面板 | 首版数据和操作 |
| --- | --- |
| GameGuide 当前计划 | 从当前游玩档案读取目标、下一步和缺口。没有档案或计划时展示相应空状态。提供继续对话、截图翻译和打开详情。档案相关操作以展示时的上下文令牌校验当前档案，档案切换后通知宿主刷新。 |
| 通用截图翻译 | 无需选择档案。提供截图翻译按钮，通过现有截图能力获取选区，由翻译提供方处理原文和译文，详情在对应结果页展示。取消框选后回到原界面。 |

## 实施顺序

1. **验证 DSH 和 Windows 接入点**。在目标 DSH 版本验证插件间注册与注销、桌面 UI 的启动退出、设置入口以及截图生命周期。参考现有 [截图插件入口](../capture/index.js)验证桌面辅助进程的启动与清理。若 DSH 无法直接承载浮窗，采用由悬浮助手插件管理的 Windows 辅助进程，DSH 侧管理注册、偏好和处理器调用，桌面进程负责渲染和窗口交互。以一个模拟面板验证两个进程间的数据与操作往返后确定实现方案。
2. **实现宿主闭环**。用两个模拟面板验证注册、切换、持久化、停用和异常隔离，再完成多屏定位、置顶、焦点和退出清理。宿主可独立于 GameGuide 验收。
3. **接入通用截图翻译**。先打通点击、隐藏浮窗、框选、恢复和结果展示。该阶段依赖截图能力及翻译提供方，验收覆盖成功、取消和失败。
4. **接入 GameGuide 当前计划**。等档案读取、计划和会话入口可用后接入真实数据，验证快速切档、继续对话、截图翻译和打开详情。最后执行两块真实面板的联合验收。

## 首版验收

| 场景 | 通过条件 |
| --- | --- |
| 面板和设置 | 两块真实面板使用同一套接口注册并可切换。分别启停和设置默认面板后重启，偏好恢复。停用或卸载当前面板后回退，全部停用时仍可进入设置。 |
| 接口和异常 | 无效声明、缺失处理器、读取超时或操作失败均能定位到来源，另一个面板仍可使用。快速从 A 切到 B 再切回 A 时，迟到的旧结果不会覆盖新结果。操作中重复点击只触发一次调用。 |
| 档案一致性 | 展示档案 A 时切到 B，再点击尚未更新的操作，处理器拒绝旧令牌并提示刷新。刷新后的内容和操作均对应 B。 |
| 窗口与焦点 | 在 Windows 普通桌面和无边框窗口中验证把手可点、展开置顶、收起后焦点可恢复。主动切到其他应用后收起时焦点留在该应用。副屏混合缩放、拔除副屏后把手仍可达。独占全屏记录窗口模式、把手可见性和交互结果。 |
| 截图交接 | 从浮窗发起截图时，选区内没有浮窗或把手。完成、取消和失败后均恢复预期状态。已停用时，迟到的截图结果不会重新显示浮窗。 |
| 插件退出 | 关闭 DSH 或停用悬浮助手后，浮窗消失。如使用辅助进程，验证进程也已退出。 |
