# GameGuide 游戏助手需求

## 产品目标

玩家在 Windows 上游玩时，可以通过快捷键框选游戏画面，翻译屏幕文字、询问任务攻略，或让助手根据当前进度给出经营、建设和资源调度建议。助手按游戏和游玩档案记住玩家已经确认的进度，下一次对话可以接着当前档案继续。

核心能力是 **Agent 针对当前问题现场编写并执行脚本**。玩家用自然语言提出目标和约束。Agent 根据截图、档案和游戏规则选择计算方法，运行代码、校验结果，再给出能在游戏中执行的建议。新增一种计算问题时，只要所需数据和规则可用，就可以由 Agent 当场生成脚本。游戏插件提供数据和规则，常用计算可以沉淀为可复用工具。

## 使用场景

### 潜水员戴夫寿司店经营

玩家前期主要抓鱼，后期发现现金不足、营业时经常要亲自上菜。他截一张招聘页问「这几个员工该招谁？」

- 从截图提取可见的候选人属性、技能和招聘费，结合档案里最近确认的员工阵容、现金目标和操作偏好，给出人选、岗位以及暂缓招聘的条件。
- 只有候选人截图时，先给条件建议。例如，玩家主要忙于上菜时优先考虑能补前厅的人。若阵容会改变结论，先问玩家现在卡在哪个岗位。口头说不清时再请他截现有员工页。
- 只有当问题扩展到「今晚卖什么」时才需要菜谱或菜单。要计算具体备多少份时，再读取库存。可用现金和想留的周转金可以直接口述。
- 玩家问「怎么多赚又少操作」时，Agent 用当前数据写脚本比较可行的备菜组合。结果列出菜单、份数、材料消耗、预计收入和人工操作。客流等未知输入用条件或区间表示。这里的自动化以游戏内员工分工、备菜计算和经营记录为例。
- 玩家确认已经招聘后更新员工阵容。打烊后可以用结算截图记录可见的收入和销量，下次潜水前据此给出带数量的捕捞清单。

### 纪元 1800 生产与布局

玩家提交生产统计和岛屿地图，问「补齐缺口，主岛尽量少占地，现有航线还得留 20 吨运力」。Agent 读取生产需求、建筑规则、可用地块和航线数据，现场写脚本比较各岛分工、建筑数量和装载方案。建议包括建设顺序、各工序的余量和航线的瓶颈。

缺少往返时间时，可以先计算航线能满足需求的最长往返时间。只知道大致面积时，可以估算建筑占地。逐格布局需要可建区域和建筑尺寸。适配后可以推荐匹配的布局模板，并评估游戏原生 Stamps 的导入或导出。

### 翻译、任务攻略与计时

- 框选后可以选择「翻译截图」「问攻略」或「翻译并分析」。OCR 提取原文和位置，助手以双语对照或截图预览标注展示译文。译文保留数量、时间及单位，标明模糊文字。游戏插件可以提供地名、角色名和道具名的术语表。
- 截图翻译适用于没有专用插件的游戏。翻译并分析时复用识别结果，结合原图、当前目标和攻略资料给出下一步。后续可按玩家确认记录任务进度。
- MOBA 的赛后复盘与局内时间点提示按游戏分别评估。实时提示的可用数据和呈现方式取决于对应游戏、模式和厂商政策。

## 入口与界面

- **左侧菜单 → 游戏助手**。首页展示已经建立游玩记录的游戏。首版可用卡片，显示游戏名、最近使用的档案、当前目标、下一步和最近活动时间。点击游戏进入详情。有多个档案时，在详情页顶部切换。首页默认按最近活动排序。
- **游戏详情 → 概览、攻略、历史对话**。概览优先显示当前档案的目标和下一步，再展示行动项、缺口及完成状态。攻略页展示已经整理的条目。历史对话按档案查看，可以继续对话，并从消息中选取文字提炼要点。
- **屏幕右侧浮窗**。游玩时收起为屏幕右边缘的小把手，唤起后可查看当前目标和下一步、继续提问、截图翻译，以及打开完整详情。浮窗与主界面使用同一份档案和会话。首版建议手动选定游戏和档案，待实测后决定是否自动跟随前台游戏。
- **截图翻译**。从浮窗或截图快捷键框选后可直接翻译，展开结果时保留原文和译文的对应关系。通用翻译可以直接使用，玩家需要时再把结果关联到某个档案。

## 当前计划

Agent 根据玩家的目标和游戏状态生成或调整计划。插件保存结构化的目标、行动项、缺口、状态和最近更新时间。详情页和浮窗用固定版面读取同一份计划，Agent 可以现场写脚本计算食材、产能或运力缺口。

例如目标是「寿司店稳定营业，减少亲自上菜」，计划可包含「补 1 名前厅员工」和「补 8 份鲨鱼肉」。缺口说明依据哪个时点的库存。玩家确认员工已经入职后，同步更新档案和行动项。浮窗默认展示下一步，定时提醒的触发规则另行讨论。

## 对话提炼与攻略

- **自动提炼**。一轮对话结束后检查新增内容，提取可复用的玩法、条件和经验。Agent 再把候选要点总结成可独立阅读的条目，查找并合并已有条目，保留适用条件及来源消息。
- **手动提炼**。玩家选中消息文字后，可以发起「提炼成攻略」或「保存为要点」。Agent 根据选区和必要的对话上下文整理标题和正文，玩家可预览、编辑，再保存。
- **记录归属**。通用规则和玩法可以归到游戏，当前库存、任务进度和基于当时条件的方案归到游玩档案。攻略条目保留来源，方便回看原对话。提炼出的建议依然是建议，实际进度由玩家确认后更新。
- **待定**。自动提炼的条目是直接展示在攻略页，还是先进入待确认列表。建议首版自动生成待确认条目，手动提炼在预览确认后直接保存。

## 代码生成与执行

1. Agent 根据当前问题选取必要的数据，标记单位、来源及缺失项。信息足以给出条件结果时先计算，只有缺口会改变决策时才追问。
2. Agent 生成本次脚本，通过运行工具执行。脚本可以做产能和成本核算、枚举组合、模拟运输或比较布局约束。玩家改动约束后，Agent 可以修改或重新生成脚本并再次运行。
3. 执行环境传入本次所需数据，限制脚本可用的文件、网络、时间和内存。运行工具返回结构化结果和错误，Agent 可以修正后再试。
4. 对结果做约束校验，例如建筑数量是否为整数、材料是否够用、航线是否超载。建议同时展示主要假设、关键数字和可执行步骤。若约束下无可行方案，指出具体冲突。
5. 脚本、输入和结果可以随计算记录保存，供复查或重跑。计算得到的方案与玩家实际完成的操作分别记录。

## 上下文与进度

- **游戏知识**由同一游戏的各档案共用，包括规则、术语、攻略和模板。游戏插件可按需要补充截图识别、数据导入和专用工具。
- **游玩档案**按游戏和存档隔离，包括员工、菜单、库存、任务、岛屿、航线和玩家偏好。每条状态记录来源及最后观察时间，区分截图可见事实、玩家确认和推测。
- **当前对话**保留本次截图和临时目标。回答时加载当前档案里相关的记录。招聘页出现过某人、建议招募和已经入职是不同事件。
- 首版可以手动选择档案，以 SQLite 保存进度。截图和玩家确认即可建立进度，无需 Steam 授权。后续可按游戏支持只读导入本地存档或日志。Steam 账号绑定可作为成就等信息的补充，游戏内详细进度仍取决于可取得的游戏数据。

## DSH 插件实现方向

首选基于 DeepSeek Harness 的插件原型。DSH 提供会话、模型调用、工具注册与可配置的 `run_code`。GameGuide 插件提供游戏档案读写、截图翻译、游戏数据和攻略查询。游戏适配按需增加，计算逻辑由 Agent 针对具体问题生成。第一阶段验证 DSH 现有界面接收截图和触发代码执行的流程。若要独立 Windows 客户端，可用 Rust 实现快捷键、框选和结果展示，通过 DSH SDK 的 stdio JSON-RPC 传递图像和问题，并接收会话事件。

实现前需要实测所选模型对游戏截图的识别效果，以及所选 DSH 运行时能否在限定权限下执行计算。公开接口可作为接入依据。 [DSH 工具与 run_code](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/tools/README.md) · [DSH SDK](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/README.md) · [图像输入协议](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/server/README.md)

## 首版验收

| 场景 | 通过条件 |
| --- | --- |
| 通用截图翻译 | 对没有专用插件的游戏提交一张截图，得到可对应原文的译文。数字和单位得到保留，模糊部分有标记。 |
| 戴夫招聘 | 仅给招聘页即可得到条件推荐。只有缺失信息会改变人选或岗位时才追问，回答纯招聘问题时无需库存页。 |
| 戴夫经营 | 提供菜单、库存和经营目标后，Agent 现场生成并执行脚本，输出可执行的备菜方案、材料约束和估算条件。 |
| 纪元临场计算 | 提供生产和航线数据后，Agent 针对未预设的约束写脚本并实际执行。修改预留运力后再次计算，可核对方案是否超载。 |
| 档案隔离与恢复 | 关闭后恢复同一档的已确认状态。切换游戏或档案时各自加载对应数据。助手建议的招聘或建设方案不会被当成已完成进度。 |

## 功能落地顺序（草案）

1. 先跑通一个戴夫档案的闭环。游戏列表进入详情，提交招聘截图，Agent 生成计划，玩家确认行动，重启后可恢复计划和历史对话。验证 DSH 左侧菜单能否通过插件扩展。
2. 加入自动和手动提炼。用同一段对话反复提炼，验证同义攻略可以合并，适用条件和来源仍可回查。
3. 接入右侧浮窗和快捷截图翻译。验证浮窗收起、唤起、回到游戏焦点，以及全屏和无边框模式下的实际表现。用一个没有专用适配的游戏验证通用翻译。
4. 用戴夫备菜和纪元航线完成临场计算验收，验证玩家修改约束后，计算结果可以更新对应计划。
